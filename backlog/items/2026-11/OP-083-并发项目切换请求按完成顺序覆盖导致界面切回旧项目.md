## 现状与证据

If the user chooses project A and then project B before A's Board request finishes, both goroutines remain active. The callback for whichever request completes last unconditionally replaces the visible project. Thus A can finish after B and switch the UI back to A even though B was the user's latest selection. Any earlier callback can also set switching=false while a newer request is still pending, so the UI stops showing the in-flight transition.

## 建议方向

Give project loads a monotonically increasing request generation or cancellable request context. Apply board data and clear switching only when the callback still belongs to the most recent selection; optionally cancel superseded requests to reduce needless service work. Apply the same rule to project/global view transitions.

## 验收标准

Delay two concurrent Board responses and complete them in reverse order after selecting A then B. The UI must remain on B, stale A data must not replace columns/tasks/detail/project-run state, and the switching indicator must remain active until the latest request settles. Repeat for project-to-global and failed latest-request paths.

## 决策记录

- 初始状态：inbox（待筛选，未经批准实施）。

Scope extension after auditing other board-load paths: openGlobal (board.go:591-643) also launches a request goroutine and unconditionally commits curGlobal/tasks and switching=false; a project selection started while it is pending can be overwritten by the older global response. Initial load (board.go:531-586) similarly commits its eventual target and clears switching without checking whether a user-initiated selection superseded it. These are the same stale asynchronous board-load callback root as openProject, not separate items.

补充项目列表刷新入口（2026-11-04）：applyEvent 收到每个 EventProjectChange 都启动独立 goroutine 调用 Projects，并在完成后无条件执行 b.projects=ps（cmd/taskboard/board.go:773-804）。每次 Projects 会查询项目活跃时间并另取全量列信息；事件快速连续到达会产生并行重复读取，较早快照也可能晚于较新快照提交，覆盖项目列表/列角色状态。与看板切换回调相同，属于异步读取缺少请求代次/合并且旧结果可提交；建议同一代次机制覆盖项目元数据刷新，并验证变更事件突发时仅提交最新快照。
