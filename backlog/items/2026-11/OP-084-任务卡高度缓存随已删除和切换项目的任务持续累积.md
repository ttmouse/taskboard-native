## 现状与证据

虚拟列表按 task ID 缓存已测卡片高度，作为离屏占位高度；该缓存仅在 board 生命周期中保存。任务删除路径只移除 b.tasks、失效 taskViewCache 并清理 motion；项目切换及全部项目加载直接替换 b.tasks，但没有同步裁剪 cardHeights。用户长时间运行客户端并浏览、删除或切换大量任务/项目时，历史 ID 对应的高度条目会留在内存中。

## 建议方向

在任务集合被替换或任务移除后，按当前 board 仍可能使用的任务 ID 裁剪 cardHeights；对全局看板要保留全部已加载项目任务的尺寸，并避免每个 SSE 更新都重复全量扫描。

## 验收标准

模拟浏览多个任务后删除/切换项目，缓存仅包含当前可用任务 ID；全局视图仍能复用当前任务高度；重复加载不会让缓存条目随历史任务数增长，虚拟列表滚动占位高度无回退。

补充发现（2026-11-04）：同属按实体 ID 生命周期未回收的 UI 状态，board.colScrolls 由 columnScroll 在首次使用列时创建（cmd/taskboard/board.go:997-1006），全仓无删除/裁剪；项目切换和 SSE 快照会替换 b.columns（cmd/taskboard/board.go:662, 870），项目删除事件可回到全局视图（cmd/taskboard/board.go:790-800）。因此在同一客户端进程中反复打开并删除项目，会连带保留访问过的列滚动状态。该表每个列条目很小，影响仍低；建议与 cardHeights 一并按当前可达 task/column ID 回收，或生命周期明确后复用/清空。

补充同类任务键缓存（2026-11-04）：还存在两张 task ID map 未及时回收。其一，SSE 中其他 Agent 更新任务时 b.recent[id] 写入 600ms 到期时间（cmd/taskboard/board.go:728-730），但删除只发生在该卡下一次实际构建 taskCard 时（cmd/taskboard/view.go:1588-1594）；虚拟化列中的屏外卡片不会构建 taskCard（cmd/taskboard/column_virtual.go:125-149），因此过期键可持续滞留。其二，sfxMuteUntil 在每次首次/过期卡片移动时写入 taskID→now+500ms（cmd/taskboard/board.go:2046-2055），全仓无 delete 或过期裁剪；每个曾移动过的不同任务都留下条目。建议把这些短期交互状态与 cardHeights 一样按可见实体生命周期统一清理，并避免逐帧全表扫描。

补充矩形缓存 bounds（2026-11-04）：可见卡片在每次 taskCard 构建后写入 b.bounds[task.ID]（cmd/taskboard/view.go:1820-1825）；虚拟化只在当前任务变为屏外时删除 bounds 项（cmd/taskboard/column_virtual.go:140-144）。remove 仅调用 forgetMotion，不删除 bounds/cardHeights（cmd/taskboard/board.go:1284-1297）；load/openProject/openGlobal/applySnapshot 替换 b.tasks 时也未按新任务集合裁剪 bounds（cmd/taskboard/board.go:569-585,598-643,653-672,870-874）。因此项目切换/删除后最后可见卡片的矩形会长期保留。clearMotion 会清理 flight/drag 相关 map，任务删除也调用 forgetMotion；这些动效 map 不属于该遗漏。建议将 bounds 与 cardHeights 一起按仍可达任务 ID 裁剪。

补充项目级 UI 状态缓存（2026-11-04）：projectRunRuntime 以 projectID 缓存自动承接渠道（cmd/taskboard/board.go:369-371），只在 startProjectRun、stopProjectRun、loadProjectRun 中设置/删除（cmd/taskboard/view.go:379-431）。收到 ProjectChange 时仅替换 b.projects，删除当前项目则异步退回全局视图，没有删除 projectRunRuntime 对应键（cmd/taskboard/board.go:773-801）。服务删除项目只阻止仍有 Active execution 的项目；空队列但运行开关已启用时仍可删除，因此该 map 项可随同一 GUI 生命周期残留。每项只是一条渠道字符串，影响低；建议在确认项目不存在的刷新回调中清理不可达 ID，并覆盖删除空队列运行项目的缓存回收。
