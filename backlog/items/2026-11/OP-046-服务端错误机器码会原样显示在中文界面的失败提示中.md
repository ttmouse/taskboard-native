## 现状与证据

错误码适合协议和日志判定，但当前桌面提示会将部分服务端代码直接展示给用户，无法说明是否需要重试、刷新或检查状态。

## 建议方向

在 GUI 展示层按稳定服务端错误码映射简短中文和可操作建议；未知值使用通用中文提示并保留诊断信息到日志/详情。不要改变 API wire code 或 contracts。

## 验收标准

覆盖 not_found、internal_error、project_busy、execution_active、未知码与网络离线错误；toast 对用户均可读且给出合适下一步，日志仍可定位原始状态码；服务端 API 契约保持不变。
