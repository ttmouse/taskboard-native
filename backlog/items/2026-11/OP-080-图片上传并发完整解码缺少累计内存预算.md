## 现状与证据

The image endpoint reads each compressed request into memory, checks dimensions against 40 million pixels, then fully decodes it before saving. The per-request limits prevent one arbitrarily large upload but do not cap aggregate decode memory across concurrent handlers. Several valid near-limit PNG uploads can each require around 160 MB of decoded RGBA data in addition to compressed input; the HTTP server has no upload-decode concurrency limit, so ordinary parallel requests can exhaust the local service process.

## 建议方向

Bound full image validation decoding across concurrent uploads and account for decoded pixel cost, not only compressed bytes. Prefer a dimension-weighted budget or equivalent bounded worker admission that keeps request memory predictable while preserving supported formats and corruption detection; return a clear retryable response when capacity is temporarily unavailable.

## 验收标准

Send concurrent valid images near the per-image pixel limit and measure peak RSS/active decoders; memory and concurrent full decodes must remain within a documented bound. Verify PNG/JPEG/GIF/WebP validation, corrupt/truncated-image rejection, ordinary upload latency, and overload responses; no image should be published before complete validation.
