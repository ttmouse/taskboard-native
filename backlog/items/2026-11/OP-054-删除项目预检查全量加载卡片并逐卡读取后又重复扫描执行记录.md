## 现状与证据

删除项目会拒绝仍有派发线程或活跃会话的项目。当前执行器在全局派发锁内读取完整任务/关系并逐项查询执行记录，而最终 Store 删除前已有一遍项目级执行记录校验。

## 建议方向

保留对 d.inflight 的保护，但改为窄化读取项目 task ID 做内存执行检查；持久化 active execution 由 Store.DeleteProject 的锁内检查作为唯一校验来源，避免每卡 Execution 往返及重复 active 扫描。确认错误仍映射为 project_busy，检查与删除之间仍由既有锁/Store 锁保障并发安全。

## 验收标准

项目含大量正文、关系、归档卡和执行记录时，删除前检查只读取 task ID，不做每卡 Execution 查询；active execution 仍被拒绝，inflight 进程即使尚无活跃持久化记录也仍被拒绝；删除内容和 409 错误契约不变，并记录大项目预检查耗时与其他项目 Dispatch 阻塞时长。
