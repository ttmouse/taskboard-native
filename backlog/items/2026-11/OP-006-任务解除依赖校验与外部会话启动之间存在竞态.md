## 现状与证据

派发路径在 Dispatcher 锁内读取任务并调用 Store.AssertUnblocked，但该 Store 方法返回后就释放 Store.mu；之后 Dispatcher 登记 inflight 并异步开始 run。期间关系 API 仍可为任务新增未完成的 blocks 依赖。会话创建后 syncRunningTaskColumn 再尝试移入进行中，阻塞校验此时才失败并写告警评论，但外部会话已经启动。HTTP handler 还额外做了一次更早的 AssertUnblocked，不能消除此窗口。

## 建议方向

为“校验阻塞关系 + 预留派发权”建立原子边界，或在外部会话创建前再次进行可序列化校验；定义并发新增阻塞关系与派发谁先赢，确保失败不会已经启动外部会话。

## 验收标准

在派发检查后、外部会话创建前确定性插入未完成 blocks 关系；系统不得启动该外部会话，或必须按明确的线性化顺序将关系写入拒绝并返回冲突。再覆盖反向顺序、Herdr/CLI 两渠道与自动承接，确认卡片位置、execution 和关系结果一致且无孤儿会话。
