## 现状与证据

Every move/reorder reads the destination column and normalizes all live cards onto contiguous multiples of 1000. For a top insertion, each existing card shifts one slot and renumber generates a separate UPDATE per card; moving between columns can additionally compact the source column. The entire statement list runs in one transaction while Store.mu remains held, temporarily blocking all project reads/writes. This is a write-amplification cost distinct from OP-070's missing index and query sort cost.

## 建议方向

Consider sparse sortable positions: place between neighbors when a representable gap exists, and rebalance a bounded region or whole column only when gaps are exhausted. Preserve stable ordering, archived-card exclusion, deterministic tie-breaking and the atomic single-writer transaction; measure rebalance frequency and write counts before adopting the scheme.

## 验收标准

For representative column sizes, record UPDATE count, transaction time and Store lock hold time for append, middle insert, top insert, cross-column move and archive. Common moves should update a constant number of task rows, with rebalance only when gaps are exhausted; task order must remain deterministic and consistent after restart and concurrent serialized moves.
