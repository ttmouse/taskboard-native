## 现状与证据

项目自动承接启动或继续队列时，已有 ended execution 的进行中卡被归入 stalledDoing，按契约应先移入「等你」并写说明。当前 pushStalledDoingCards 在没有 review 列或 MoveTask 因版本冲突失败时，把该卡 ID 作为 fallback 返回；调用方把 fallback 加入 ready 并交给 dispatchProjectCard，后者会对仍在进行中的卡调用 Dispatch。Dispatch 对 ended execution 允许创建新会话，因此一个无法移列等待人工的已处理卡会被自动再次执行，可能重复代码/文件/外部副作用。

## 建议方向

把“移列失败”的结果与“待派发”分开表示：已结束的卡移列失败时保留当前执行记录与自动承接开关，设置明确等待人工的详情并停止推进；只有没有 execution 记录、且从未开始的卡才能按新会话派发。对因并发版本冲突的情况重新读取最新卡片后仍不得绕过契约重派。

## 验收标准

覆盖项目没有 review 角色列、MoveTask 发生版本冲突、正常成功移列、进行中卡没有 execution 记录、待办卡可派发等路径。前两种必须保持开关并等待人工且绝不调用 Dispatcher.Dispatch；成功移列后推进队列；从未开始的卡仍按顺序派发。
