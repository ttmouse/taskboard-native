真实桌面 Host、真实 Grok 模型、真实工具执行，测试看板使用独立 HTTP 端口、SQLite 数据库和工作目录。转发器只影响测试连接，不修改生产凭证或停止桌面端。

## 结果

`TestLiveDesktopRecoveryFlow` 通过，耗时 81.35 秒。

1. 给测试连接提供错误 token：真实桌面桥接拒绝鉴权。卡片退回待办，没有创建桌面任务。
2. 在测试转发器定点返回上游授权拒绝：执行记录标为 failed，卡片退回待办，不自动反复重试。此步是故障注入，不是真实撤销模型渠道凭证。
3. 重派同一卡片，真实桌面端接收后切断测试跟踪连接：记录变为 disconnected，不误报成功；同时重复派发返回 409，切换 Codex 也返回 409。
4. 关闭并重新启动测试 HTTP 服务，重新打开同一 SQLite 数据库：自动接续原会话，未再次发送创建请求。真实工具输出的文件恰好为 `START\nDONE\n`，只执行一次；模型结果回写，卡片进入评审，执行记录 succeeded。
5. 第二张卡的真实任务被桌面端接收后，转发器丢弃接收回执：记录为 unknown，保留原会话标识。
6. 对第二张卡再次派发：只跟踪原会话，文件恰好为 `ONCE\n`，只执行一次；结果回写并进入评审。

两项真实任务合计只有两次转发到桌面端的创建请求。步骤、任务 ID、会话 ID 和状态见同目录 `desktop-recovery-2026-10-26.json`。测试产物位于 `/tmp/taskboard-full-flow-20261026/workspace/`。

## 回归范围

- SQLite 原执行记录的重启接续，不重新创建会话。
- 旧版桌面接收评论的接续，包括按外部会话 ID 查询及分页读取结果。
- 会话启动暂不可读、尚无 turn.end 时不得报完成。
- 等待人工确认、失败/中断终态、空结果、桌面不可用、禁止回退 CLI。

`go test -race ./internal/executor ./internal/service ./internal/store`、`go vet ./...` 和竖向列表/快速创建针对性回归通过。全量 `go test ./...` 未全绿：四个拖拽动效用例失败，另有一次 Pi 取消用例失败；Pi 取消用例单独带竞态检测重复三次通过。上述全量限制不等同于本次恢复验收通过。

## 边界

- 授权故障不能靠把入口改成桌面端消除；本轮未撤销或修改任何真实上游账号的授权。
- 重启覆盖的是看板服务、执行器和 SQLite 的重建；没有杀死 DSH 桌面端或全局断网。
- 未验证断电/文件系统损坏、多个看板服务同时写同一数据库等情形。
- unknown 且桌面端确实没有该会话时，保留记录供人工核对，不自动创建第二个会话。
