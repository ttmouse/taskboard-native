# 执行 Agent 自行回写闭环验收 · 2026-10-26

当前职责：接收任务的 Agent 按 `manage-taskboard-native` 自行读取原卡、认领、实现、验证、写结果评论、迁移状态并 GET 确认。程序只递交上下文、保存连接/会话记录、防重复提交及接续；不代写工作结果、不自动认领或移动任务。

## 已修改

- 更新共享技能及仓库镜像，写明认领、验证、正常交付、受阻、版本冲突和断连后的回写规则。
- 派发说明提供实际看板地址、原卡 ID、状态列 ID 和 X-Agent 身份，明确由执行 Agent 完成闭环。
- 移除执行器自动认领、自动移入评审/退回待办和代写完成摘要的逻辑，DSH/Codex/Pi 共用此职责。
- execution 的 returned 只表示会话交回，独立于原卡业务状态；空文字、正常退出均不能代替任务结果或验收。

## 真实 DSH 验收

`TestLiveDispatchSkillHandoff`：75.96 秒通过。Agent 从随机端口看板读取仅在原卡评论中的口令，自己从待办认领至进行中（version 1→2），写入署名 DSH 的【执行结果】评论，再移到评审（version 2→3），最后 GET 确认。程序未代写该评论，也未修改卡片状态。工具轨迹见 `agent-owned-workflow-2026-10-26-tools.json`。

`TestLiveDesktopRecoveryFlow`：299.60 秒通过，使用真实桌面 Host、模型、文件与隔离看板数据库：

1. 真实桥接鉴权失败：未创建任务，原卡状态不变。
2. 定点注入上游式 403：记录技术失败，原卡不被程序认领或迁移。
3. 重派、接收后断开测试连接：重复派发及切换渠道被拦截。
4. 重启测试服务并接回原会话：Agent 继续实现、写结果并移入评审；产物恰好 START/DONE 一次，没有重复提交或执行。
5. 桌面已接收但回执丢失，再次派发只接续原会话；Agent 自行回写并进入评审，文件恰好 ONCE 一次。
6. 受阻任务：Agent 先认领、写明依赖缺失及下一步，再退回待办并 GET 确认。会话正常结束、execution=returned，卡片仍为待办，未被程序误移入评审。

步骤状态证据见 `agent-owned-workflow-2026-10-26.json`。上游 403 为测试转发器注入，没有撤销真实账号授权或中断用户网络。

## 回归与边界

`go test -race ./internal/executor ./internal/service ./internal/store`、`go vet ./...` 通过。负向测试验证：伪 Agent 只正常退出并打印结果时，程序既不认领卡片、不迁移状态，也不代写工作结果。CLI 的职责由相同路径及假 CLI 回归覆盖，本轮真实执行验收针对 DSH。

模型或工具突然中断时，Agent 可能来不及写回；程序只保存技术异常并保留原卡状态，接续后由 Agent 核对产物并补回写，不猜测业务结论。用户明确验收后才进入完成。
