# 实时同步要求

## 原则

- **禁止轮询**。卡片状态、列位置、评论与指派变更必须经 **WebSocket 或 SSE** 从本应用内建服务推送到 GUI。
- GUI 收到事件后 **就地更新**（行/卡移动、状态徽章、计数），用原生过渡动画；**不要**整页刷新或重建整表。
- 其他代理经 **CLI / MCP** 读写时，同一推送通道必须立刻反映到已打开的窗口。

## 断线恢复

- 每次 SSE 连接先注册订阅，再在 Store 锁内读取一致的全板快照与当前事件序号，发送 `board.snapshot`。
- 快照读取期间发生的写入先进入订阅队列；发送快照后只发送序号更大的事件。较早事件已包含在快照中，会被跳过。
- 网络断开、服务重启或订阅队列溢出后，客户端重连并接收新快照，从而覆盖断线期间漏掉的增量事件。恢复不依赖进程内事件历史或 `Last-Event-ID` 重放。
- 快照是恢复路径，不是周期轮询；连接正常时仍只接收 SSE 增量事件。

## 建议事件

最少：`task.created` · `task.updated` · `task.moved`（含 from/to 列）· `task.archived` · `comment.added` · `project.changed`。

载荷带 `id`、`version`、变更字段；客户端用 version 做乐观合并，冲突时拉一次详情再对齐。

## 动画

跨列移动：卡片从源列滑入目标列（或等效原生过渡），列表插入/删除带动画；失败回滚到推送前位置。

## 非目标

浏览器轮询、依赖 DSH 在线才能刷新、仅种子库无服务端推送。
